# Conventions

How this repo is laid out, built, checked and released. These rules were decided in [Grilling: repo conventions and tooling](../../.scratch/modern-frontend/issues/10-grilling-repo-conventions-and-tooling.md) and the tickets that amended it. The stack itself is [ADR-0001](../adr/0001-application-stack.md).

Sections marked _(ticket NN)_ describe something a later build ticket adds; that ticket fills the section in when it lands.

## 1. Layout

```
src/
  main.tsx              calls boot() in app/
  routeTree.gen.ts      generated by TanStack Router from src/routes (committed, never edited)
  app/                  boot (section 5): i18n, the browser check, /config.json, sign-in, the API client, the router
  routes/               TanStack Router file routes, kept thin: they import a feature's page
  features/<area>/      one folder per screen area (households, accounts, categories, …)
  components/ui/        shadcn/ui parts, added with `make ui-add` (section 4)
  components/           shared parts we build: the amount input, the Category picker, the data table
  api/                  the pinned contract, generated types, the client (section 5)
  lib/                  pure helpers; money.ts is the money module (section 6), theme/ the themes (section 11)
  locales/en/*.json     message files, one namespace per feature
  test/                 test setup shared by every test, and the MSW server
  mocks/                the mock API: MSW handlers typed by the contract, and mock mode (section 7)
e2e/                    Playwright tests, run against the mock build (section 7)
scripts/                Node scripts in TypeScript: the API generator and the contract check
types/                  declarations for untyped dev tools
```

Tests sit next to the code they test, as `*.test.ts(x)`.

**Boundaries** (`eslint-plugin-boundaries`, in `eslint.config.ts`). The rule that matters: **a feature never imports another feature.** Shared code moves down into `components/`, `lib/` or `api/`. The full set of allowed imports:

| From | May import |
|---|---|
| `src` root files | `app`, `routes` |
| `app` | everything, including `mocks` (only a mock-mode build loads them) |
| `routes` | `app`, features, `components`, `ui`, `api`, `lib` |
| a feature | itself, `components`, `ui`, `api`, `lib` |
| `components` | `components`, `ui`, `api`, `lib` |
| `components/ui` | `ui`, `lib` |
| `api`, `lib` | `api`, `lib` |
| `mocks` | `mocks`, `api`, `lib` |
| tests | additionally `app`, `test` and `mocks`; `src/test/` may also read `api` (the contract) |

A file outside these folders fails lint (`boundaries/no-unknown-files`).

## 2. Commands

- **Node runs only in Docker.** Never install Node, npm or a version manager on your machine.
- **`.node-version`** is the one source of truth for the Node version (the Active LTS). The Makefile reads it for the `node:<version>-bookworm-slim` image, and `package.json` `engines` mirrors it.
- **Make is the only entry point.** Each target runs an npm script inside the container. npm scripts hold the real definitions, so CI calls them directly.
- `node_modules` and the npm cache live in named Docker volumes, so Linux packages never mix with the host's. A target installs from `package-lock.json` first whenever the lock file is newer than the last install.

| Target | What |
|---|---|
| `make dev` | dev server on https://localhost:5173, `/api` forwarded to `API_PROXY_TARGET` (see "The dev loop") |
| `make dev-cert` | make the dev server's certificate with the mkcert CA, once |
| `make dev-config` | write `public/config.json` from the local cluster's OIDC ConfigMap |
| `make build` | static build into `dist/` |
| `make preview` | serve the build on http://localhost:4173 |
| `make lint` | ESLint, the Prettier check, then actionlint |
| `make actionlint` | check `.github/workflows` |
| `make format` | Prettier, then ESLint fixes |
| `make typecheck` | `tsc -b` |
| `make test` | Vitest |
| `make generate` | regenerate the route tree and the API types |
| `make contract-check` | check `src/api/openapi.yaml` against the pinned backend release |
| `make contract-update ref=…` | copy the backend's contract at a tag or commit, then regenerate |
| `make audit` | `npm audit` of the runtime dependencies, high and above |
| `make image` | build the UI image (`IMAGE`, default `wallet-accountant-ui:local`) |
| `make image-test` | build it, run it as the chart does, check the UI contract |

| `make ui-add c="…"` | add shadcn/ui parts with the pinned CLI; `o=--overwrite` to update them (section 10) |

There are no git hooks: CI enforces the checks.

### The dev loop

The dev server runs like the real thing: HTTPS, the API under `/api` on the same origin, and sign-in through Zitadel.

1. **Once:** run `make local-ca` in `wallet-accountant`, so this Mac trusts the mkcert CA. Then run `make dev-cert` here. It writes `.certs/` (git-ignored) with a certificate for `localhost`.
2. **The local cluster running** (`make local-up` in `wallet-accountant`): run `make dev-config`. It writes `public/config.json` (git-ignored) from the cluster's `wallet-accountant/wallet-accountant-oidc` ConfigMap. It's a Make target rather than the npm script the spec named, because `kubectl` runs on the Mac, not in the Node container.
3. `make dev`, then open https://localhost:5173.

- **Where `/api` goes:** Vite forwards `/api` unchanged to `API_PROXY_TARGET`. The default is the cluster's app at `https://wallet.localhost:18443`, reached from the container through `host-gateway` and trusted through the mounted mkcert CA. With the backend's `make run` instead, use `make dev API_PROXY_TARGET=http://host.docker.internal:8080`.
- **Redirect URIs:** signing in from `https://localhost:5173` needs Zitadel's `web` app to accept that origin's redirect URIs. That's the environment repo change in the backend handoff (`oidc.zitadelSetup.web.extraRedirectUris`).

## 3. TypeScript

`tsconfig.base.json` holds the flags shared by both projects: `tsconfig.app.json` (the browser code in `src/`) and `tsconfig.node.json` (the config files and `scripts/`, which Node runs as TypeScript directly). On top of `strict`:

- `noUncheckedIndexedAccess`
- `exactOptionalPropertyTypes`
- `noImplicitOverride`
- `noFallthroughCasesInSwitch`
- `noPropertyAccessFromIndexSignature`
- `verbatimModuleSyntax`
- `erasableSyntaxOnly`: no `enum`, no `namespace`, no parameter properties

`noUnusedLocals` and `noUnusedParameters` stay off, so half-written code doesn't block a build; the linter reports unused code instead.

**Exceptions.** When a library makes a flag unworkable, turn off that one flag in the narrowest tsconfig and record it here with the reason. There are none yet.

`tsconfig.e2e.json` covers `playwright.config.ts` and `e2e/`, which need Node and DOM types together.

The `@/` path alias exists only because shadcn/ui parts import `@/components/…`; our own code uses relative imports, which the boundaries rule reads.

An untyped dev tool gets a small, typed declaration in `types/` (see `types/eslint-plugin-jsx-a11y.d.ts`), never an implicit `any`. A browser feature TypeScript's lib doesn't declare yet gets one next to the code that uses it (`src/api/json-source-text.d.ts`), removed once the lib has it.

## 4. Lint and format

- **ESLint 9**, pinned until `eslint-plugin-jsx-a11y` supports 10, with typescript-eslint `strict-type-checked` + `stylistic-type-checked`. `any` and the non-null `!` are errors. Zero warnings allowed; unused `eslint-disable` lines are errors.
- **Plugins:**
  - `react-hooks`
  - `jsx-a11y`, strict
  - `@tanstack/eslint-plugin-router`
  - `@tanstack/eslint-plugin-query`
  - `i18next/no-literal-string` for JSX text (off in tests)
  - `import/no-extraneous-dependencies`: app code may only import `dependencies`; config files, `scripts/`, `src/test/`, `src/mocks/` and tests may import `devDependencies`
  - `boundaries` (section 1)
- **Prettier** with a 100-column width formats code and config. Markdown is prose and isn't formatted.
- **Generated files** (`src/routeTree.gen.ts`, `src/api/schema.gen.ts`) and the contract copy (`src/api/openapi.yaml`) are excluded from lint and format.
- **shadcn/ui parts** in `components/ui/` meet the same ESLint rules:
  - Fix them when they are added.
  - An `eslint-disable` line is allowed only there, each with a reason, and marked `// local:` like any other change. Example: `label.tsx`, a generic wrapper whose uses wrap their control.
  - Edit a part only when a wrapper in `components/` or a prop can't do the job, and mark each change `// local:`. For example, `dialog.tsx` takes its close button's name from the message files.
  - Prettier skips `components/ui/`, so the parts keep upstream's formatting and an update's diff shows only real changes.
- **TanStack Router's `redirect()` and `notFound()`** are thrown by design, so `@typescript-eslint/only-throw-error` allows them.

## 5. API client

### The pinned contract

- `src/api/openapi.yaml` is a copy of the backend's `api/openapi.yaml`, never edited by hand.
- `src/api/CONTRACT_VERSION` names the backend release it belongs to. Images carry it as the `wallet-accountant.min-api-version` label.
- **To move to a new backend release:** run `make contract-update ref=v0.2.0`. It copies the file at that tag, sets `CONTRACT_VERSION` and regenerates. Commit all three, then fix whatever no longer type-checks: a renamed path or field fails at every call site.
- `make contract-update ref=<commit>` copies from a commit without changing `CONTRACT_VERSION`. It's for following an unreleased backend change.
- The `contract` CI job fails when the copy differs from the file at `CONTRACT_VERSION`. Until that tag exists, it warns instead.
- **Current state:** `CONTRACT_VERSION` is `v0.1.0`, the backend's first release, which isn't tagged yet. The copy comes from backend `main` at `5788472`.

### Generated types

- `scripts/generate-api.ts` writes `src/api/schema.gen.ts` with openapi-typescript (`make generate`). It adds two mappings:
  - `format: decimal` (only `Money.amount`) becomes `Decimal`: exact decimal text, typed `` `${number}` ``.
  - An `x-extensible-enum` becomes its known values plus any other string: ``"INCOME" | "EXPENSE" | "INTERNAL" | `${string}` ``. TypeScript folds the known values into the string, so the type is a plain string with the values as documentation, and an unknown value type-checks, as the contract promises more may come. Always handle the unknown case.
    - Not `string & {}`, which keeps the literals: openapi-fetch's `Readable` maps that intersection as an object, so a response's value stops being a string.
    - Code that names the values keeps its own list and tests it against the contract with `extensibleEnum("AccountKind")` (`src/test/contract.ts`), as `components/account-labels.test.ts` does.
- The `generated` CI job regenerates and fails on any difference.
- openapi-typescript 7.13 declares only TypeScript 5 as a peer. TypeScript 6 keeps the same compiler API, so an `overrides` entry in `package.json` gives it our TypeScript.

### The client

`src/api/client.ts` exports `createApi({ baseUrl, auth })`. The app calls it once at boot with `apiBaseUrl` from `/config.json` and the sign-in session. Screens get the result with `useApi()` (`src/api/context.ts`): `fetchClient` (openapi-fetch) and `api` (openapi-react-query hooks, e.g. `const { api } = useApi(); api.useQuery("get", "/currencies")`). Calls are typed by path and method. Middlewares do the work every call needs:

- **Exact money** (ADR-0002, `src/api/exact-json.ts`):
  - **Responses** are re-read with a `JSON.parse` reviver that keeps every numeric `amount` as its source text: `100.00` stays `"100.00"`, and ETH keeps all 18 places.
  - **Request bodies** are written with `JSON.rawJSON`, so a decimal-text `amount` leaves as an exact JSON number, which is what the backend requires.
  - Nothing else in the app turns JSON into amounts.
- **Idempotency-Key** (`src/api/idempotency.ts`): every POST, PUT, PATCH and DELETE gets one. Screens never handle keys; a write is a plain `api.useMutation`. A request is identified by its method, URL and body:
  - the same request sent again after an error reuses its key;
  - a changed input gets a new key;
  - after a success the key is forgotten.
- **Problems** (`src/api/problem.ts`): every error response reaches the caller as an RFC 9457 problem with a `status`. When the server sent none (an empty 503, say), one is made with `type: "about:blank"`. A network failure is a thrown `TypeError`. Screens show a problem's `title` and `detail` as sent. Problems with extra fields (`rows`, `reasons`, `statement_import_id`) are rendered by the screens that own them, by which fields they carry; there is no list of problem types.
- **The bearer token** (`src/api/auth.ts`): every request carries the signed-in User's access token. A 401 renews the token once and resends the request once. Concurrent 401s share one renewal, because refresh tokens rotate. If renewing fails, or the new token is refused too, the session has ended (see "Boot and sign-in").
- **Freshness and retries** are the Query client's defaults (`src/app/query-client.ts`, `src/api/retry.ts`):
  - Reads are fresh for 30 s, are refetched on focus, and retry on network errors and 5xx, three attempts in all.
  - Writes retry twice, with the same key, on network errors and 502, 503 and 504 only.
  - A write's submit button is disabled while `isPending`.

### Routes, forms and errors

- **Router context:** the router is made at boot with `{ api, queryClient }` (`src/app/router.ts`), so a route's `beforeLoad` and `loader` can read before the screen renders: `loader: ({ context: { api, queryClient } }) => queryClient.query(api.queryOptions("get", "/currencies"))`. The screen then reads the same data with `api.useSuspenseQuery`, already in the cache.
- **Failed loads:** a loader that throws shows `LoadError` (`src/components/load-error.tsx`): the problem's text and "Try again". A 404 becomes `notFound()`, which shows `NotFound`. Both are the router's defaults for every route, so a failure inside a Household shows in the shell's content area and the sidebar stays. They render their own `<main>` only outside the shell (`components/main-landmark.tsx`).
- **The shell** (`features/shell/`) is the layout route `routes/households/$householdId/route.tsx`. Its loader reads the Household, the Households and `GET …/accounts`, and every screen inside reads them from the cache. Opening Add Account from the sidebar or a screen goes through `useOpenAddAccount()` (`components/add-account.tsx`), which the layout provides next to the dialog, so no feature imports another.
- **Forms** use React Hook Form with a Zod schema (`zodResolver`). The schema mirrors the contract's limits per field, with messages from the message files. A field's error is linked to it with `aria-describedby` and `aria-invalid`.
- **A form's failed write** shows `FormAlert` (`src/components/form-alert.tsx`) at the top of the form, and the input stays. `useErrorText` (`src/components/error-text.ts`) picks the words: the problem's `title` and `detail`, or ours for a network failure or a response with no problem.
### Boot and sign-in

`src/main.tsx` calls `boot()` (`src/app/boot.tsx`), which goes in this order:

1. **Messages** (i18n).
2. **The browser check:** JSON source text access, which needs Chrome and Edge 114, Firefox 135 or Safari 18.4. Without it the unsupported-browser screen shows, and the app never starts, so it can never show a wrong amount.
3. **`/config.json`**, checked by the Zod schema in `src/app/config.ts`. Unknown keys are dropped, never refused, as the UI contract requires. A missing or wrong file shows "Wallet Accountant can't start" with the details, for whoever runs it.
4. **The app** (`src/app/app.tsx`):
   - **Sign-in:** oidc-client-ts and react-oidc-context sign in through Zitadel's `web` app. They use the authorization code with PKCE and the scopes `openid profile email offline_access`, keep tokens in `sessionStorage`, and renew in the background with the refresh token. There is no backend-for-frontend.
   - **Gate:** `SignInGate` shows the app only to a signed-in User. Anyone else goes to Zitadel, with the current page in the sign-in state.
   - **Coming back:** the callback on `/auth/callback` (a reserved route) returns to that page. Only same-origin paths are accepted.
   - **Session ended:** when renewal fails, `SessionEndedDialog` says "Your session has ended" and signs in again to the same page. Input in an open form is lost.
   - **Audience:** `audience` from the config isn't sent; Zitadel puts the API's audience in the `web` app's tokens.

## 6. Strings and formatting

- Every user-facing string lives in `src/locales/<language>/<namespace>.json`, one namespace per feature, registered in `src/app/i18n.ts`. Keys are type-checked: `t("nope")` fails `make typecheck`.
- A new language is a new folder of the same files.
- Money, numbers and dates are formatted with `Intl` for the locale, never by hand.
- **Money goes through the money module**, `src/lib/money.ts`, the only code that reads an amount's digits:
  - `formatMoney` keeps every place the amount carries, with a plain minus: `€1,234.50`, `-€3.50`, `ETH 1.000000000000000001`.
  - `parseAmountInput` reads what a User typed in their locale.
  - `differenceForDisplay` is the one use of `big.js`. Its result is shown, never sent.
- **Amounts are typed** into `components/amount-input.tsx`. It is a text field (never `type="number"`) that:
  - reads the locale's separators and a typed minus;
  - refuses more places than the currency has;
  - keeps canonical decimal text;
  - formats only on blur, so the caret never moves while typing.
- **Display rules:** no colour for income or expense; colour marks only differences, always with text or an icon. Table amounts are right-aligned with tabular digits.
- Backend problem text (`title`, `detail`) is shown as sent and isn't translated.

## 7. Testing

- **What a good test is**: it drives the UI the way a User does (by role, label and keyboard) and asserts on what the User sees or what goes over the network. It never mocks the API client or hooks.
- **Unit and component tests**: Vitest with Testing Library in jsdom (`vite.config.ts`, setup in `src/test/setup.ts`). Pure logic gets plain unit tests. Our own parts are driven by keyboard and role.
- **API mocking**: MSW at the network level, never mocking the client or hooks.
  - Handlers in `src/mocks/` are typed by openapi-msw from the contract, so a drifting mock is a type error.
  - Tests run against `src/test/server.ts`, and a request with no handler fails the test. A test adds its own handlers with `server.use(...)`.
  - A mock response with money goes through `withExactAmounts`, so amounts arrive as exact JSON numbers, as the backend sends them.
  - The same handlers serve the browser in mock mode.
- **Mock mode** (`vite --mode mock`, `make dev-mock`, the e2e build) runs the app with no backend and no Zitadel:
  - `src/mocks/browser.ts` starts MSW's service worker with the test handlers, plus `/config.json`.
  - It puts a signed-in mock User where oidc-client-ts keeps one.
  - **Mock data** (`src/mocks/db.ts`) is stateful: redeeming an Invitation or creating a Household changes what the next read returns. Tests keep it in memory and reset it after each test (`mockDb.reset("new-user")` picks another start). Mock mode keeps it in the tab's `sessionStorage`, so it survives a reload.
  - **Scenarios:** `?mock-scenario=new-user` on any page starts the tab over as someone who hasn't redeemed an Invitation, `registered` as a User with no Household, `household` (the default) with "Home" (Accounts Main and Credit card) and "Cabin" (no Accounts). The Invitation code the mock accepts is `WELCOME-2026`.
  - **Failures:** `?mock-fail=<path end>:<count>` makes the next `<count>` API requests whose path ends that way fail with a 503, for testing "Try again". A read makes three attempts, so `:3` fails a load once.
  - Vite serves and builds MSW's worker only in this mode, from the installed `msw`, into `dist-mock/`. The real build contains none of it: boot imports the mocks behind `import.meta.env.MODE === "mock"`, which Vite removes from other builds.
- **End-to-end** (`e2e/`, `make e2e`):
  - **Where it runs:** Playwright in its official image, whose version is read from `@playwright/test` in `package.json`, against the mock build served by `vite preview`. Chromium only for now.
  - **The gate:** every test calls `expectAccessible(page)` (`e2e/axe.ts`) once per screen and state, such as a dialog open or errors shown. It runs axe's WCAG 2.2 A and AA rules and fails on any violation.
  - **Exceptions** are passed per scan with a reason, as named sets in `e2e/axe.ts`, each backed by a test of the behaviour that makes the rule not apply. The one so far, `comboboxListOpen`: a Base UI Combobox with its list open hides the rest of the page from assistive tech (`aria-hidden-focus`), and leaving the input closes the list.
  - **Storage:** MSW keeps its own bookkeeping in `localStorage`, unguarded. So an e2e test that blocks storage refuses only the app's keys, and the unit tests cover a `localStorage` that throws on any access.
- **Theme contrast**: `src/lib/theme/themes.test.ts` checks every token pair of all eight themes (section 11).
- **Manual accessibility pass before each release**, on every screen, keyboard first and then VoiceOver (Safari, macOS):
  1. Tab through the whole screen. Focus is always visible, never hidden under a sticky header or a toast, and moves in reading order.
  2. Every control works with the keyboard alone: Enter or Space activates; arrows move within radio groups, menus and comboboxes; Escape closes dialogs and popups, and focus returns to what opened them.
  3. VoiceOver reads each control's name, role and state, and each form error as it appears, with its field.
  4. At 200% zoom and at 320 px wide, nothing is cut off and the page doesn't scroll sideways (wide tables scroll in their own box).
  5. With "Reduce motion" on, nothing animates.
- No coverage threshold.

## 9. The image and releases

### The image

`Dockerfile` builds the app in the Node image from `.node-version`, then serves `dist/` from `/srv` with Caddy (`docker/Caddyfile`). It meets the backend's UI contract (`../wallet-accountant/docs/architecture/ui-contract.md`):

- **Server**: plain HTTP on 8080, Caddy's admin API and config persistence off.
- **User**: numeric uid 10001, so Kubernetes' `runAsNonRoot` can check it.
- **Filesystem**: a read-only root filesystem, with Caddy's files under the writable `/tmp` the chart mounts.
- **Capabilities**: the Caddy binary's low-port capability is removed, because the chart drops every capability.
- **Paths**: `GET /healthz` answers 200. Any other path that isn't a file returns `index.html`, except under `/assets/`, where a missing file is a 404.
- **Caching**: `/assets/*` files get `public, max-age=31536000, immutable`; everything else gets `no-cache`.
- **Runtime config**: `/srv/config.json` is where the chart mounts it (`ui.configPath`). The image ships none, so without the mount it's a 404.

`docker/test-image.sh <image>` runs the image the way the chart does: `--read-only`, an empty `/tmp`, `--cap-drop ALL`, `no-new-privileges`, and `config.json` mounted. It then checks each point above.

### Releases

`.github/workflows/release.yaml` publishes to GHCR, as the backend does:

| Pushed ref | Image `ghcr.io/mumia/wallet-accountant-ui` | GitHub Release |
|---|---|---|
| `main` | `main-<sha>` (7 characters), for testing | no |
| Tag `v1.2.3` | `v1.2.3` | yes |
| Tag `v1.2.3-rc.1` | `v1.2.3-rc.1` | yes, marked pre-release |

- Any other tag fails before anything is published. A tag must be annotated and point into `main`.
- The image is built for `linux/amd64` only.
- Every image gets a build provenance attestation and a keyless cosign signature, and the `wallet-accountant.min-api-version` label from `src/api/CONTRACT_VERSION`. The image test checks the label is there.
- The release notes are the tag's message, then the image and its digest, then GitHub's list of merged pull requests.

To release:

```sh
git switch main && git pull
git tag -a v1.2.3   # the editor opens for the release notes
git push origin v1.2.3
```

- **If the workflow fails after publishing:** fix forward with the next patch version. Never move, delete or reuse a published tag.
- **The first release** creates the GHCR package. Make it public once, in the package settings, so clusters pull it without credentials.

Verify an image:

```sh
gh attestation verify oci://ghcr.io/mumia/wallet-accountant-ui:v1.2.3 --repo mumia/wallet-accountant-ui
cosign verify ghcr.io/mumia/wallet-accountant-ui:v1.2.3 \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/mumia/wallet-accountant-ui/\.github/workflows/release\.yaml@refs/'
```

## 10. Dependencies

- Exact versions only (`save-exact=true` in `.npmrc`), with `package-lock.json` committed. Install with `make npm a="install -E <package>"`.
- **Renovate** (`renovate.json`) runs weekly. It groups npm minor and patch updates, GitHub Actions, Node, and the tools pinned by a `# renovate:` comment. It holds ESLint below 10, TypeScript below 7, and `@types/node` on the Node major in `.node-version`.
- **shadcn/ui parts:**
  - **Updated by hand**, when an upstream fix is worth having: `make ui-add c="<parts>" o=--overwrite`, then review the diff and put back the `// local:` changes. Renovate bumps only the CLI.
  - **`cn` package:** the registry's parts import `cn` from shadcn's own npm package `cn`, which replaced `clsx` and `tailwind-merge`, so there is no `lib/utils.ts`.
  - **Adding:** `make ui-add` runs with no terminal attached, so the CLI never waits at a hidden prompt.
- **Fonts** are bundled from Fontsource variable packages (`@fontsource-variable/*`), never loaded from Google Fonts. The browser downloads only the active preset's font.
- **Playwright:** its image version follows `@playwright/test`, so Renovate's npm update moves both.

## 11. Look and feel

- **Stack:** shadcn/ui on Base UI (the `base-nova` style) with Tailwind 4. The static CSS is `src/app/theme/index.css`. The prototype on branch `prototype/look-and-feel` is the visual reference, not code to copy.
- **Themes:** four presets (Ledger, Teal, Ink, Warm) × light and dark make eight token profiles, in `src/lib/theme/themes.ts`. Each profile starts from its scheme's neutral base and overrides what its preset changes.
  - `applyAppearance` sets the tokens, the preset's font and radius, `color-scheme` and the `dark` class on `<html>`. So the contrast test reads exactly the values the browser uses.
  - **Contrast rules:**
    - text needs 4.5:1, including muted text on every surface and destructive text on its tinted button;
    - a control's edge (`input`), a checked fill (`primary`) and the focus ring (`ring`) need 3:1 on what they sit on;
    - `border` draws decorative lines only, and is exempt.
  - **Changing a token** means running `make test`. If tuning visibly changes a preset's character, the User looks at it.
- **The User's choice:** a preset, plus Light, Dark or System. The default is Ledger in Dark.
  - It is set in the Appearance dialog (`src/components/appearance-dialog.tsx`) and applied live.
  - It is saved in `localStorage` under `wallet-accountant.appearance`, applied before the first render, and follows the system's setting under System.
  - Storage that is missing or throws is ignored: the app works and just doesn't remember.
- **Density:** comfortable only.
- **Motion:** with "reduce motion", animations and transitions are cut to nothing (`index.css`).
- **Tables:** amounts use the `tabular` class for equal-width digits.
