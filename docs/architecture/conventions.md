# Conventions

How this repo is laid out, built, checked and released. These rules were decided in [Grilling: repo conventions and tooling](../../.scratch/modern-frontend/issues/10-grilling-repo-conventions-and-tooling.md) and the tickets that amended it. The stack itself is [ADR-0001](../adr/0001-application-stack.md).

Sections marked _(ticket NN)_ describe something a later build ticket adds; that ticket fills the section in when it lands.

## 1. Layout

```
src/
  main.tsx              boot: i18n, then the router
  routeTree.gen.ts      generated by TanStack Router from src/routes (committed, never edited)
  app/                  boot wiring: i18n, router, later config, OIDC and the Query client
  routes/               TanStack Router file routes, kept thin: they import a feature's page
  features/<area>/      one folder per screen area (households, accounts, categories, …)
  components/ui/        shadcn/ui parts (ours to edit, see section 4)
  components/           shared parts we build: the amount input, the Category picker, the data table
  api/                  pinned openapi.yaml, schema.gen.ts, client.ts  (ticket 03)
  lib/                  pure helpers: Intl formatting, problem+json, …
  locales/en/*.json     message files, one namespace per feature
  test/                 test setup shared by every test
types/                  declarations for untyped dev tools
```

Tests sit next to the code they test, as `*.test.ts(x)`.

**Boundaries** (`eslint-plugin-boundaries`, in `eslint.config.ts`). The rule that matters: **a feature never imports another feature.** Shared code moves down into `components/`, `lib/` or `api/`. The full set of allowed imports:

| From | May import |
|---|---|
| `src` root files | `app`, `routes` |
| `app` | everything |
| `routes` | `app`, features, `components`, `ui`, `api`, `lib` |
| a feature | itself, `components`, `ui`, `api`, `lib` |
| `components` | `components`, `ui`, `api`, `lib` |
| `components/ui` | `ui`, `lib` |
| `api`, `lib` | `api`, `lib` |
| tests | additionally `app` and `test` |

A file outside these folders fails lint (`boundaries/no-unknown-files`).

## 2. Commands

- **Node runs only in Docker.** Never install Node, npm or a version manager on your machine.
- **`.node-version`** is the one source of truth for the Node version (the Active LTS). The Makefile reads it for the `node:<version>-bookworm-slim` image, and `package.json` `engines` mirrors it.
- **Make is the only entry point.** Each target runs an npm script inside the container. npm scripts hold the real definitions, so CI calls them directly.
- `node_modules` and the npm cache live in named Docker volumes, so Linux packages never mix with the host's. A target installs from `package-lock.json` first whenever the lock file is newer than the last install.

| Target | What |
|---|---|
| `make dev` | dev server on http://localhost:5173 (HTTPS and the `/api` proxy arrive in ticket 04) |
| `make build` | static build into `dist/` |
| `make preview` | serve the build on http://localhost:4173 |
| `make lint` | ESLint, then the Prettier check |
| `make format` | Prettier, then ESLint fixes |
| `make typecheck` | `tsc -b` |
| `make test` | Vitest |
| `make generate` | regenerate the route tree |
| `make check` | every CI check, in CI's order |
| `make npm a="…"` | any npm command, e.g. `make npm a="install -E zod@4"` |
| `make shell` | a shell in the Node container |
| `make install` | reinstall from `package-lock.json` |
| `make clean-deps` | drop the `node_modules` volume |
| `make ui-add c="…"` | add shadcn/ui parts _(ticket 05)_ |

There are no git hooks: CI enforces the checks.

## 3. TypeScript

`tsconfig.base.json` holds the flags shared by both projects: `tsconfig.app.json` (the browser code in `src/`) and `tsconfig.node.json` (the config files). On top of `strict`:

- `noUncheckedIndexedAccess`
- `exactOptionalPropertyTypes`
- `noImplicitOverride`
- `noFallthroughCasesInSwitch`
- `noPropertyAccessFromIndexSignature`
- `verbatimModuleSyntax`
- `erasableSyntaxOnly`: no `enum`, no `namespace`, no parameter properties

`noUnusedLocals` and `noUnusedParameters` stay off, so half-written code doesn't block a build; the linter reports unused code instead.

**Exceptions.** When a library makes a flag unworkable, turn off that one flag in the narrowest tsconfig and record it here with the reason. There are none yet.

An untyped dev tool gets a small, typed declaration in `types/` (see `types/eslint-plugin-jsx-a11y.d.ts`), never an implicit `any`.

## 4. Lint and format

- **ESLint 9**, pinned until `eslint-plugin-jsx-a11y` supports 10, with typescript-eslint `strict-type-checked` + `stylistic-type-checked`. `any` and the non-null `!` are errors. Zero warnings allowed; unused `eslint-disable` lines are errors.
- **Plugins:**
  - `react-hooks`
  - `jsx-a11y`, strict
  - `@tanstack/eslint-plugin-router`
  - `@tanstack/eslint-plugin-query` _(ticket 03)_
  - `i18next/no-literal-string` for JSX text (off in tests)
  - `import/no-extraneous-dependencies`: app code may only import `dependencies`; config files, `src/test/` and tests may import `devDependencies`
  - `boundaries` (section 1)
- **Prettier** with a 100-column width formats code and config. Markdown is prose and isn't formatted.
- **Generated files** (`src/routeTree.gen.ts`, later `src/api/schema.gen.ts`) are excluded from lint and format.
- **shadcn/ui parts** in `components/ui/` _(ticket 05)_ meet the same rules. Fix them when they are added; an `eslint-disable` line is allowed only there, each with a reason. Edit a part only when a wrapper or prop can't do the job, and mark each change `// local:`.

## 6. Strings and formatting

- Every user-facing string lives in `src/locales/<language>/<namespace>.json`, one namespace per feature, registered in `src/app/i18n.ts`. Keys are type-checked: `t("nope")` fails `make typecheck`.
- A new language is a new folder of the same files.
- Money, numbers and dates are formatted with `Intl` for the locale, never by hand. Money goes through the money module _(ticket 03)_.
- Backend problem text (`title`, `detail`) is shown as sent and isn't translated.

## 7. Testing

- **What a good test is**: it drives the UI the way a User does (by role, label and keyboard) and asserts on what the User sees or what goes over the network. It never mocks the API client or hooks.
- **Unit and component tests**: Vitest with Testing Library in jsdom (`vite.config.ts`, setup in `src/test/setup.ts`). Pure logic gets plain unit tests. Our own parts are driven by keyboard and role.
- **API mocking**: MSW at the network level with handlers typed by openapi-msw, so a drifting mock is a type error. The same handlers serve dev and e2e _(ticket 03)_.
- **End-to-end**: Playwright in its official Docker image, against the built app with MSW, with an `@axe-core/playwright` scan per screen and state that fails on any violation _(ticket 05)_.
- **Theme contrast**: a unit test of each theme's tokens _(ticket 05)_.
- **Manual accessibility pass before each release**: keyboard only, then VoiceOver, on every screen _(the checklist arrives with ticket 05)_.
- No coverage threshold.

## 8. CI _(ticket 02)_

GitHub Actions on every PR and push to `main`. Each job mirrors a `make` target. Actions are pinned to SHAs.

| Job | What | Lands in |
|---|---|---|
| `lint` | ESLint, Prettier check, actionlint | 02 |
| `typecheck` | `tsc -b` | 02 |
| `test` | Vitest | 02 |
| `image` | build the Caddy image, then test it as the chart runs it | 02 |
| `audit` | `npm audit --omit=dev`, high | 02 |
| `generated` | regenerate the API types and the route tree, then `git diff --exit-code` | 03 |
| `contract` | `src/api/openapi.yaml` equals the file at the pinned backend tag | 03 |
| `e2e` | Playwright with MSW and axe | 05 |

## 9. Releases _(ticket 02)_

As in the backend:
- a `vX.Y.Z` tag publishes `ghcr.io/mumia/wallet-accountant-ui:vX.Y.Z` and a GitHub Release
- a push to `main` publishes `main-<sha>`
- every image gets a provenance attestation and the `wallet-accountant.min-api-version` label

## 10. Dependencies

- Exact versions only (`save-exact=true` in `.npmrc`), with `package-lock.json` committed. Install with `make npm a="install -E <package>"`.
- Renovate weekly, grouped _(ticket 02)_.
- shadcn/ui parts are updated by hand: `--overwrite`, then review the diff and re-apply the `// local:` changes _(ticket 05)_.
- Fonts are bundled from Fontsource variable packages, never loaded from Google Fonts _(ticket 05)_.
- TanStack Table v9.
